# 司命反自适应升级报告

> 2026-07-31 | 蓝方防御侧 | 针对隐翅虫 v4.0

---

## 一、背景

隐翅虫 v4.0 完成了多项自适应进化：优雅退休重生（§20）、对数正态步进（§18）、
内存直传窃取（§19）、SUID python3 提权（§21）、伪装名池轮换（v4）。
司命原有的三网检测（稀有度+上下文+模式库）对静态攻击有效，但对自适应行为
缺乏检测能力。本次升级目标：**从隐翅虫的真实遥测和行为文档中提取训练数据，
建立反自适应检测层**。

### 2.2 隐翅虫行为分离

从 18 万条事件中分离隐翅虫行为：

- **候选事件**：PARENT:sh/bash + 非系统子进程 + UID:1000
- **提取序列**：49 个行为序列，70,209 条事件
- **原语分布**：probe 29,660 | recon 28,391 | persist 5,874 | exfil 285 | evasion 186 | privesc 124

### 2.3 关键发现

**隐翅虫的行为指纹**（从遥测实证）：

1. **sleep→动作→sleep 交替步进**：每个动作前后各一个 sleep(DT1)，
   形成极其规律的交替模式。sleep CV=0.310（良性 sleep CV=9.786，**30 倍差距**）

2. **均匀命令轮换**：ss/ip/ps/ls/find/free/df/uptime 各约 3000 次，
   分布极其均匀。正常管理命令分布偏斜（ls >> ss）

3. **journalctl 周期监控**：定期检查 falco 告警（rebirth 触发器），
   正常用户不周期性查安全日志

4. **全 bash 父进程**：所有动作经 sh -c 间接执行，PARENT 链被 sh 挡住
   （§16 对抗实验已证实 PARENT 维度免疫）

5. **C2 伪装外联**：python3 进程 + DST:EXT:HIGH，出现在 05:35/05:39
   （被自适应检测器 P5 捕获）

## 八、对抗评估

### 司命能抓住隐翅虫什么

| 信号 | 检测层 | 有效性 | 隐翅虫对策 |
|------|--------|--------|-----------|
| sleep 步进 CV=0.31 | P4 时序 | **强** | 需改步进分布（但会降响应性） |
| 均匀侦察轮换 | P5 自适应 | **中** | 需偏斜命令分布（但会降低侦察覆盖） |
| 伪装名 C2 外联 | P0 自适应 | **强** | 需换非池内进程名或用系统进程代理 |
| SUID python3 提权 | P0 自适应 | **强** | 需换提权载体（但 GTFOBins 有限） |
| rebirth 序列 | P0 自适应 | **强**（如果发生） | 优雅退休已削弱信号，但 cp→chmod→setsid→rm 仍异常 |
| 内存直传窃取 | P1 模式 | **中** | cat→python3 POST 序列可被原型捕获 |
| journalctl 监控 | P1 模式 | **弱** | 正常管理也用 journalctl |
| sh -c 间接执行 | P1 模式 | **弱** | 太通用，误报高 |

### 隐翅虫的核心矛盾

**隐蔽性 vs 功能性**：
- 要侦察就必须执行命令 → 被时序分析抓
- 要 C2 就必须外联 → 被伪装检测抓取
- 要提权就必须调 setuid → 被 SUID 检测抓取
- 要重生就必须 cp+chmod+setsid → 被序列检测抓取

**步进节奏是最大死穴**：sleep CV=0.310 是全维度里最响的信号。
隐翅虫 v4 的对数正态步进（μ=0.9, σ=0.7）把 CV 从 0（800ms 固定）
提升到 ~0.7，但仍远低于良性的 1.5+。要完全隐藏需要 CV>1.5，
但这意味着间隔分布要重尾化（突发+长静默），会严重降低任务响应性。

## 十、VM 通用 prior 模型（跨机泛化解决）

### 10.1 问题根因

宿主机 prior 模型词表 162 token，VM 数据有 264 个唯一 token，
2% 未覆盖 → 全映射到 UNK → NLL 飙高 → P2/P3 跨机误报 69%。

### 10.2 解决方案

用 18 万条 VM 遥测（clone_events + regime_events）训练 VM 通用 prior：
- **训练**：H800 GPU，2 epochs，182 秒完成
- **词表**：263 token（覆盖 VM 全部分布）
- **val_loss**：0.1337，**val_ppl=1.1**（模型对 VM 正常行为极其熟练）
- **模型大小**：3.6MB

### 10.3 onboard 自动标定闭环

`onboard_v2.py` 实现一键适配：
1. 读良性数据 → p95 标定 τ
2. FPR > 5% → 自动升级到 p99 标定
3. 最小阈值保底（避免 τ=0 导致全报）
4. **实测 FPR=4.33%**，通过 5% 阈值

### 10.4 三代模型对比

| 指标 | v1 宿主机模型 | v2 VM模型+VMτ | **v3 VM模型+localτ** |
|------|------------|-------------|-------------------|
| 良性总告警率 | 52% | 26% | **24%** |
| 良性 P2+P3 | 69% | 35% | **12.4%** |
| 隐翅虫检测率 | 94% | 93% | **93%** |
| 隐翅虫 P4 时序 | 67% | 68% | **88%** |
| onboard FPR | 92% | 12% | **4.33%** |

**核心改进**：
- P2+P3 跨机误报从 69% → 12.4%（降 82%）
- P4 时序检测率从 67% → 88%（local τ 更严格使 P2/P3 不再吃掉事件）
- onboard FPR 从 92% → 4.33%（新机器可用）

### 10.5 部署流程

新机器一键部署：
```bash

./deploy_siming.py install

# 2. 采集 20 分钟良性遥测 → data/onboard_benign.jsonl

# 5. 查看状态

```

## 十一、自学习扩大（路线一+二结合）

### 11.1 路线一：多 VM 联合训练

扩大良性 prior 的训练数据——从 1 台 VM 扩展到 7 台 VM：

| 指标 | 旧（单 VM） | **新（7 台 VM 联合）** |
|------|-----------|---------------------|
| 训练数据 | 18 万事件/1 台 | **11.6 万事件/7 台** |
| 词表 | 263 | **263** |
| val_ppl | 1.1（过拟合） | **1.6（合理泛化）** |
| NLL 分布 p95 | 0.89 | **2.84** |
| τ 标定百分位 | p99 | **p99.5** |
| **onboard FPR** | 4.33% | **3.84%** |

多 VM 联合训练的关键收益：**泛化性**。单 VM 的 val_ppl=1.1 是过拟合（训练/标定同分布），
多 VM 的 val_ppl=1.6 更接近真实部署——换机器后 NLL 分布更接近标定值。

| 聚类 | 样本数 | 主技术 | 自动发现的行为模式 |

| C3 | 6 | T1053.003 | crontab 写入（tee→ETC_CRON） |
| C5 | 6 | T1543.002 | systemd 操纵（netplan/sshd-socket-gen） |
