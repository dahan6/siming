## 一、系统概述

司命是一台**行为语法安全引擎**：把主机/网络行为当作一门语言，用小型语言模型学习
"正常行为"的语法，语法不通者即异常；用原型学习记忆"已知坏"的模式；按时序节奏
捕捉自适应敌手；按置信度分级响应（告警→建议→自动消杀）。

核心主张：**小模型 + 好语法 + 足量真实数据 > 大模型 + 少数据**。
整个检测底座 0.87M 参数，可在边缘设备实时运行（CPU 可推理）。

### 五道检测网（v4 融合，独立可拆）

| 网 | 回答 | 机制 | 依赖投喂 | 状态 |
|---|---|---|---|---|
| P0 自适应高危 | 敌手自变异/提权了吗？ | 自适应事件检测（rebirth/SUID/变形） | 否 | 上线 |
| P1 已知坏 | 这像哪种攻击技术？ | 原型学习码本 + 模式库（ATT&CK） | 是（需标注样本） | 闭环验证通过 |
| P2 上下文 | 见过的 token 这么组合对吗？ | 分维度 NLL 判定（8 槽位 τ） | 否 | 上线 |
| P3 稀有度 | 这个 token 我见过吗？ | UNK + 高 NLL | 否（本机自学习） | 上线 |
| P4 时序 | 动作节拍像机器吗？ | 每进程步进 CV 分析 | 否 | 上线 |
| P5 自适应低危 | 有可疑弱信号吗？ | 自适应弱信号聚合 | 否 | 上线 |

融合判定优先级 P0 > P1 > P2 > P3 > P4 > P5，同事件去重。
设计原则：免投喂的先验是底座，需投喂的原型是增量——依赖数据的组件永不做单点。

| 级 | 触发 | 动作 | 误差成本 |
|---|---|---|---|
| P0/P1 | 自适应高危/原型模式命中 | 自动消杀（cleanup 映射）+ 二次验证 | 低（归因对才动手） |

## 三、技术原理

### 3.1 token 语法（所有能力的根基）

每个事件编码为 8 个离散 token：

```
ET:CONN PROC:bash ARGV:N2P PC:TMP PARENT:python3 UID:1000 DST:EXT:HIGH DT2
```

| 槽位 | 语义 | 设计意图 |
|---|---|---|
| ET | 事件类型（EXEC/CONN） | 行为大类 |
| PROC | 进程名 | 行为主体 |
| ARGV | 参数骨架（数量+URL/IP/路径/base64 特征位） | 抹掉内容保留形状，天然脱敏 |
| PC | 敏感路径类目（ETC_SYSTEMD/HOME_RC/SSH_KEYS/TMP 等） | 补回"写哪个文件"——可分性的关键 |
| PARENT | 父进程 | 上下文关系（谁拉起谁） |
| UID | 用户 | 权限维度 |
| DST | 目标分类（EXT:HIGH/LAN/NONE 等） | 网络意图抽象，泛化性来源 |
| DT | 与前事件的时间间隔桶（1ms~60s 七档） | 聚合流节奏参考（≠每进程节拍，见 §3.7） |

关键设计哲学：**抽象粒度决定检测上限**。ARGV 只记形状不记内容（隐私合规 +
防对抗填充），但 PC 类目把"路径语义"补回来——初版没有 PC 时，tee 写 rc.local /
.bashrc / ld.so.preload 三个技术嵌入不可分（对比学习 loss 卡 3.0），加 PC 后收敛到 0。

### 3.2 行为语法先验（无监督底座）

- TinyGPT 因果 Transformer：d_model=128、4 层 4 头、ctx=128，**0.87M 参数**（词表 240）
- 学习 p(x_t | x_<t)，纯正常数据自监督，val ppl≈1.1（接近"背下来"）
- 收敛极快：epoch 1-2 即收敛（0.87M 对该语法容量过剩）
- 异常分 = 惊讶度（事件内 token NLL），EWMA(α=0.3) 平滑做窗口统计
- INT8 量化（torchao PTQ）：3.57MB→1.95MB，零掉点，CPU 可部署

### 3.3 分维度判定（上下文识别的释放）

发现：事件分取 max 时，单个稀有 token 掩盖其余维度信号。
改进：8 槽位各自标定 τ（留出集 p995，下限 1.0 防退化），任一维超线即报，
告警附命中维度。实测证据：同前缀下 PARENT:python3 惊讶度 10.52 vs
PARENT:bash 0.07（差 150 倍）——上下文敏感性真实存在且已被释放。

### 3.4 阈值标定哲学

- 全局 τ = 基线 NLL p995；分维度 τ = 各槽位 p995（floor 1.0）
- **纯调阈无解的定量证明**（r0 数据）：FPR≤1% 需 τ≥8，但此时检出余量塌缩到
  0.98x；τ=2.435 时余量 3.2x 但 FPR=3.75%。双判据交集为空——压缩正常分布
  尾部只能靠数据量，不能靠移动阈值
- 数据量路线实测：FPR 3.75%→1.75%→1.00%（事件 8.7万→26.8万→43.6万）

### 3.5 原型学习（已知坏的模式库）

- 冻结编码器出 128d 事件嵌入（mean-pool，嵌入存盘，迭代零重跑）
- 每 ATT&CK 技术 K=3 个原型向量，对比学习（同技拉拢/异技推远/良性推远，margin 0.5）
- **码本 = learned 模式库**：10 技术 × 3 原型 × 128d ≈ 80KB，天然防臃肿
- 良性 hard negative 训练 + 自适应半径收紧（攻击 p99 与良性 p1 中点）——
  网络版实测留一 90.6%、良性误报 0.2%（墨城 fw_proto.py 复用此法）
- 增量协议：命中现有半径=已知变种只计数；半径外已知技术=K+1 局部重训；
  全新技术=开新码位；码本版本化可回滚

### 3.6 时序 CV 分析（P4，对抗自适应敌手的专用面）

- 每进程步进间隔的变异系数 CV = std/mean
- 检测线 CV < 1.5 判为机器节拍
- **对自适应敌手的最强判别**：AAA 步进 CV=0.310 vs 良性 sleep CV=9.786（30× 分离）
- 见 §十 E1 实验：CV 面的失效边界与语法面补位

### 3.7 DT token ≠ 节拍检测（重要的概念澄清）

E1 实测发现：**DT 槽位在重尾时序敌手面前零触发（0%）**——DT token 量的是
聚合事件流的相邻间隔，不是每进程的动作节拍。当敌手用 log-normal 重尾间隔时，
其 burst 段在 DT 面上不注册。每进程节奏检测必须由时序面（per-process CV）承担。
这是论文必须写清的分工，避免读者误解 DT 维度的作用。

### 3.8 评估方法论（用血泪换的纪律）

1. **留出窗口必须是分布不是快照**：800 事件（≈20 秒）被突发主导，与 20000 事件
   （≈8 分钟）结论完全反转
2. **训练窗口必须避开自身作战活动**：用含攻击采集活动的时段训基线，τ 膨 5.6 倍
3. **观察者污染是头号误报源**：监控/采集/防御基础设施自身流量必须进语料或显式标记
4. **先验必须本机自训**：跨机迁移 92.5% 误报；universal prior 到 defense-atomic-0
   也 48% 误报 + 45% UNK——唯一解是本机自训 + 本地 τ（E1 实测再次确认）

### 4.3 外部基线对比（补丁实验，5 seeds）⭐

| 架构 | 参数 | AAA rove 检出(EWMA) | AAA bee 检出(EWMA) | FPR(EWMA) |
|---|---|---|---|---|
| DeepLog-keys (LSTM, 事件键) | 0.30M | 76.7% ±9.0% | 93.1% ±1.6% | 0.00% |
| DeepLog-full (LSTM, 8-token) | 0.33M | 100% ±0.0% | 100% ±0.0% | 0.00% |
| TinyGPT (司命, 8-token) | 0.87M | 100% ±0.0% | 100% ±0.0% | 0.00% |

**核心论点：表示 > 架构**。事件键表示下 AAA 惊讶度 p50=3.6，8-token 语法下
LSTM 14.7 / Transformer 18.3（单调递增）。LSTM 在完整语法上即可 100%，
证明语法表示贡献了主要检测增益。

### 4.4 公开基准 ADFA-LD（补丁实验）

| 变体 | 宏检出率(融合) | FPR |
|---|---|---|
| bigram（连续对） | **31.56% ±0.32% (CI95 ±0.40%, n=5)** | 1.83% |
| skip-1 bigram | 29.68% ±0.72% | 1.72% |
| skip-2 bigram | 27.83% ±0.82% | 1.72% |
| DeepLog-LSTM 参照 | **32.16% ±2.13% (n=3)** | 1.83% |

负结果：跳步 bigram 不优于连续 bigram。ADFA 上 LSTM 与 Transformer 差异
不显著（32.2% vs 31.6%），内外一致印证"表示 > 架构"。
Creech 2013 SOTA ~60-70% @ FPR 1%（差距来自特征工程非序列架构）。

### 4.5 OOV 硬子集（回应"分布失配"质疑）⭐

| 架构 | rove 词表内检出 | bee 词表内检出 |
|---|---|---|
| DeepLog-keys | 15.9%（崩塌） | 56.3% |
| DeepLog-full | 99.8% | 96.3% |
| TinyGPT（重训） | 100% | 100% |
| **TinyGPT（生产模型 host-r3-clean）** | **100%** | **100%** |

**完整语法模型在纯词表内事件上仍 ~100% 检出**——它抓字段组合违规（高 NLL），
不是词表外 token。生产模型 bee 词表内子集 p50=21.8 vs τ=2.6（8.4×）。
只有 keys-only 基线靠 OOV。这一条把"分布失配"质疑转化为加分项。

### 4.6 E1 时序失效边界（2026-09-10 靶场实测）⭐

| σ 档 | 实测 CV | CV 面检出 | 单事件语法暴露 | 聚合显著性 |
|---|---|---|---|---|
| 0.3 | 0.297 | 是 | 8.6% | p=2.6e-8 |
| 1.13 | 1.470 | 是（压线） | 9.3% | p=2.7e-9 |
| 1.25 | 1.733 | **否（逃逸）** | 8.9% | p=7.0e-9 |
| 1.75 | 3.180 | **否（逃逸）** | 9.6% | p=1.2e-9 |

**CV 可被重尾间隔绕过（审稿人漏洞真实），但逃逸留下统计显著的语法指纹
（3.3× 异常率升高，聚合 p≈1e-9）——多面融合的必要性被实测证明。**
详见 §十。

## 七、工程纪律与运营约束

1. 计算一律 nice 19，不抢占同机其他训练；GPU 可用但不驱逐
2. 红蓝物理隔离：不读红方项目、不用红方数据、消杀只在防御 VM
3. 长任务后台化且禁短超时
4. 训练/验证窗口避开自身作战活动时段（基线污染三连教训）
5. 基础设施白名单：防御管道进程组进语料或显式标记
6. 一切结论用双向 sanity check 验证（正常留出+合成异常）
7. 样本/模式入库必经暂存区+人工过审（数据投毒防线）
8. **先验必须本机自训**——跨机一律配本地 τ 校准，且优先本机重训

## 八、对抗实验记录（红蓝实测）

### 四轮演进（v1→v4）
- v1 宿主机模型：跨机失效（onboard FPR 92%）
- v2 单 VM + VM τ：FPR 降到 12%
- v3 单 VM + local τ：4.3%
- v4 多 VM + p99.5：**3.84%**（达标）；AAA 检测稳定 93%

### 隐翅虫（AAA）对抗
- 真实破绽：DT 800ms 周期 +38、T1053 命中 +3
- 良性形态躲过原型网（良性形态有效）
- v3 进化：宿主频率跟随、渐稳减速、rebirth 自变异
- 司命三个新把手：rebirth 自爆序列、频率跟随耦合度、loot 轮询

### AAA 对抗强度量化（补丁实验）
- 时序拟态证据：DT KL 散度 rove 1.05 → bee 0.54（向良性迁移，频率跟随生效）
- 最大破绽：进程词汇（KL 7.3；AAA 37 词 vs 良性 88 词）
- 与文献锚点：gym-malware/MERLIN/MAB-Malware 仅变异 API/字节、无时机适应；
  AAA 具备宿主频率跟随+渐稳减速+rebirth 自变异（运行时行为层适应）——更强

## 十、E1 时序失效边界实验（2026-09-10）⭐

**科学问题**：把节拍 CV 拉过检测线（1.5）的敌手，在其他观测面上暴露多少？

### 设计
defense-atomic-0 VM；敌手动作集固定（24 recon 命令），只变时序分布；
间隔 ~ LogNormal(σ) 均值固定 7.5s；σ ∈ {0.3, 1.13, 1.25, 1.75} × 150 动作；
良性驱动全程交错；tracee 采集；VM-local TinyGPT 自训（词表 171）。

### 结论（三个判定）
1. **CV 漏洞真实**：σ≥1.25 越过检测线，时序面失效（复现审稿人质疑）
2. **单事件语法面弱**：逃逸档暴露 ~9% = 良性 2.7% 的 3.3 倍，不足可靠区分
3. **聚合语法面翻盘** ⭐：逃逸档异常事件数 ~32 vs 良性期望 ~9.5，
   二项检验 p≈1e-9——逃逸留下统计显著指纹

**论文论断修订（强版本）**：CV 可被重尾间隔绕过，但绕过的形态在语法面留下
统计显著的暴露——多面融合的必要性被实测证明，比原论断更强。

**诚实边界**：语法暴露部分来自敌手命令集与良性的分布差异，严格拟态良性
命令分布的敌手会压低它——"in our adversary family" 边界。

报告：`reports/e1_cv_boundary_range.md`；Figure：`figures/fig_e1_cv_boundary_en.png`

## 十a、E3 异质工作负载基线（2026-09-10）

**科学问题**：良性基线 95% ssh 过于同质——检测结论在负载多样性下是否成立？

### 设计
7 台 VM（Ubuntu 24.04）三角色：dev×3（gcc/git/pip）、web×2（http 服务/日志/流量）、
desktop×2（文档/浏览/不规律节奏）；各跑独立负载驱动 90 分钟 + tracee；
25,632 事件；VM-local TinyGPT 逐角色训练 + LOVO + 跨角色评测。

### 结论
1. **异质性证实**：三角色 token 分布明显不同（dev EXEC 58%/web 67%/desktop 70%）
2. **逐角色达标**：val_ppl 1.32~1.58，留出 FPR 0~0.66%，合成攻击检出 3/3
3. **LOVO 跨机泛化 FPR = 0.00%**（7 折全过）——v4 onboarding 协议在异构负载下完美成立，
   **不过拟合单一负载**（正面回答同质性质疑）
4. **跨角色不对称**：web 训 → 其他角色 19%/14.2%（迁移差），dev/desktop 训 → web
   0.9%/0.6%——web 最特异，再次印证"必须本机自训"

报告：`reports/e3_heterogeneous_workload.md`；结果：`data/e3_raw/e3_analysis.json`

## 十b、E4 OpTC / DARPA TC 公开基准（2026-09-11，云端 A800）⭐

**科学问题**：公开多主机数据上的检测率/FPR 与跨机泛化（补外部可复现性）。

### 设计
OpTC（[FiveDirections/OpTC-data](https://github.com/FiveDirections/OpTC-data)，Inria 修正版）：
500 台 Windows 10 端点 eCAR 事件；eCAR→8-token 适配；良性期 sep16 12 台 client
自训（36 万事件，词表 117）；3 红队场景（sc1=09-23/sc2=09-24/sc3=09-25），
Inria 修正版 ground truth 标定攻击事件，流式选择性打分。

### 结果（检出率随对抗强度递减）
| 场景 | 目标 | 检出率 | 良性 FPR |
|---|---|---|---|
| sc1（PowerShell/cmd 链） | SysClient0201/0402 | **82.3% / 81.5%** | 23.3% / 24.4% |
| sc2 | SysClient0501/0005 | **65.1% / 87.0%** | 8.4% / 6.8% |
| sc3（拟态低慢） | SysClient0051/0351 | **42.0% / 22.7%** | 5.3% / 4.7% |
| **均值** | — | **63.4%** | — |

### 结论
- ✅ 公开多主机基准检出 22~87%（均值 63%），外部可复现
- ✅ 良性留出 FPR=0%，良性期多机训练有效
- ⚠️ **诚实边界**：(a) 强拟态场景（sc3）检测率有限（22-42%）；
  (b) **跨日 FPR 漂移 0%→5-24%**（sep16→sep23-25 时间漂移）——
  印证论文"必须本机自训 + 定期重训"的论断

## 十一、墨城防火墙（网络版，姊妹项目）⭐

位置：`~/mocheng-firewall/`（独立于 defense-lab，复制改造）

把司命的行为语法模式从进程/syscall 迁移到网络流——传统防火墙按 IP/端口静态
过滤，墨城学习正常流量的**序列分布**，检测"用合法端口干非法事"。

### 网络流 7-token schema
PROTO / DIR / SRCNET / DSTNET / PORTCLS / SIZECLS / DT（对应司命 8-token 的网络映射）

### 五网融合检测（P0→P1→P_NDR→P2→P3）
- P0 原型：TinyGPT 128d 嵌入 + 对比学习码本（网络攻击 DNA）
- P1 模式：ATT&CK 映射规则（端口扫描/C2信标/数据外泄/横向移动/DNS隧道）
- **P_NDR 周期检测**：总序列间隔 CV——C2 换端口换协议也躲不掉"每 30s 必外联"
  （来自隐翅虫 §4.5 的关键洞察：flow 级检测会被通道交替规避，总序列才是杀招）
- P2 上下文 / P3 稀有度（同司命）

### 实测（合成数据）
85/85 攻击检出（五类零漏报），良性 EWMA 误报 0.10%；NDR 对隐翅虫级抖动
（U(0.5,1.5)）CV=0.27 仍可检出；原型留一 90.6%、良性误报 0.2%

### 工程化
iptables 执法（TTL 自动过期、持久化、fail-closed、篡改检测、白名单）、
conntrack -E 实时采集、INT8 量化（1.9x 零掉点）、Prometheus metrics、
fw_ctl CLI、setup.sh 一键安装、systemd 服务、16/16 单测。

**关键教训（与司命一致）**：先验必须本机自训——合成模型在真实 conntrack 上
100% 误报，本机真实流量自训后执法级误报归零。

## 十三、补充设计（容易被忽略的）

1. **词表增长曲线 = 基线健康指标**：词表收敛才说明行为空间探完
2. **数据投毒审计**：定期用留出良性集审计原型半径漂移
3. **隐私合规天然性**：token 只记形状不记内容——采集侧完成脱敏
4. **模型/码本版本化**：prior.pt + prototypes.jsonl 配对版本号，可整对回滚
5. **失效安全设计**：任一组件失效降级不崩溃——码本丢失→退回纯先验；
   先验损坏→退回模式库；永远保留"只告警不动手"的全局开关
6. **成本叙事**：GPU 训练以小时计、推理 CPU 可跑——与"大模型安全方案"
   形成成本数量级差异，商业化核心论据
7. **DT token 的分工**（E1 新）：DT 量聚合流间隔，每进程节拍由时序面承担——
   论文必须写清，避免误读
