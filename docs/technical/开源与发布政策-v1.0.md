# 开源与发布政策（Open Source & Release Policy）

**版本：v1.0 · 生效日期：2026-09-07 · 本政策公开发布并持续维护**

---

## 一、总原则

本项目（司命 Siming 及其关联安全研究）的发布遵循以下原则：

1. **发布科学，不发布武器。** 公开发布的范围是：问题定义、检测方法、测量方法、防御工具、研究数据与学术论文。不公开发布任何可直接用于侵入、控制他方系统或规避他方防御的功能性产物。
2. **生成器比生成物更敏感。** 对能够持续产出功能性产物的训练管线、数据来源及相关基础设施，适用比产物本身更严格的保留标准。
3. **诚实清单。** 所有发布物如实标注已知限制与适用范围。限制清单是项目可信度的一部分。
4. **政策公开。** 本政策本身公开，接受社区监督；发布记录随版本持续更新。

## 三、计划发布（分波进行）

以下类别将在脱敏审查与合规核对完成后分波发布。

**研究设施与工具**

- 本地隔离靶场搭建手册与基础设施脚本（libvirt 隔离网络、梯度环境、遥测与快照还原闭环）
- 时序/周期检测工具（检测侧）：面向 C2 轮询等机器节律的总序列检测方法

**数据**

- 攻击行为遥测数据集：**受控研究环境内**自适应对抗体的行为遥测，脱敏后发布，供检测器训练与评测使用（DOI 存证，CC BY 4.0）
- 命令与控制流量样本（脱敏 pcap），支撑网络侧检测研究

**测量与基准**

- 对抗测量方法论：多商业检测引擎同机对抗实验的测试设计、矩阵与判据
- 自适应对抗评测基准规范：episode 结构、指标与评分协议，供第三方评估其检测器在自适应威胁下的表现

**分析与论文**

- 破绽案例分析（防御视角写作，不含复现步骤）
- 自适应体存活策略涌现的测量报告：策略类别、涌现顺序与均衡分析；仅含测量结果与行为级描述，不含训练管线与权重
- 规避策略研究（**仅文字性说明与测量统计**）：自适应体规避机制的行为学描述、分布类型与参数区间、检测意义；不含实现代码、权重、可执行配置等在用功件
- 概念与立场论文：数字生命体架构概念框架（脱敏审查版）、威胁模型形式化（落点为防御启示）、协同进化经济学分析

**标本化发布**

对功能保留物，可能以"标本"形态发布其解剖学信息——**功能死亡、形态保留**：

- 去逻辑代码解剖切片（保留结构风格，移除全部操作性逻辑，不可编译）
- 权重统计切片（分布、谱、决策面可视化等统计与可视化产物）

判定标准：任何能使功能性产物复活（恢复运行、被重训练或被直接部署）的发布形态均不属于标本，不予发布。

## 四、不予公开发布的内容

按类目保留，不逐项列举：

- 自适应对抗智能体（论文中称 AAA，Adaptive Adversarial Agent）的本体：全部源码与编译产物
- 命令与控制基础设施
- 训练所得的存活策略权重（公开发布渠道）
- 训练管线、防御课程细节与训练数据来源

保留理由：上述内容具有直接的武器化潜力。本做法参照前沿安全研究机构的结构化访问（structured access）惯例，是负责任的披露姿态，而非隐匿——保留物的存在、类目与正当获取途径均已在本文档中公开说明。

注：保留的仅是**功能性实现**。上述类目的文字性说明与测量统计不属于保留范围，按 §三发布。

## 五、封存存证与受控访问

1. **封存存证。** 功能保留物（模型权重、训练管线及关联产物）全量冻结并计算 SHA256 摘要，经可信时间戳服务存证，用于确立研究优先权；可应学术机构正当要求提供存证查验。
2. **受控访问。** 学术机构确有复现需求的，可申请受控访问：
   - 签署书面协议（限定研究用途、禁止再分发、禁止部署于未授权环境）
   - 申请方身份与用途经审核
   - 交付物限于权重与最小化推理说明，**不含训练管线与数据来源**
   - 保留完整访问日志
3. **黑盒评测（规划中）。** 计划提供托管评测服务：防守方提交检测器，在受控隔离环境中接受自适应对抗体评测，仅返回评测分数——任何功能性产物不离开受控环境。

## 六、发布治理流程

每次发布前执行：

- [ ] 脱敏审查：移除内部网络拓扑、主机命名、地址信息、内部代号与可识别操作习惯
- [ ] 模型权重记忆回吐检查：防范训练数据中的敏感字符串经权重泄露
- [ ] 代码路径与依赖扫描：确认不残留指向未公开项目的引用
- [ ] 聚合风险审视：将已公开内容作为整体评估，确认未逼近可复现功能性产物的建造指南
- [ ] 标本复活测试：逐件确认标本形态不可恢复功能
- [ ] 平台政策核对（发布平台对安全研究内容的政策）与适用法律法规核对
- [ ] 法律顾问审查最终发布清单
- [ ] 版本历史清理（git 历史压缩后发布）

发布分波进行，每波之间设观察期，视社区与平台反馈调整后续波次。
