# Outline — 论文 1（实验论文）

**标题候选**: *Behavior Grammar: Tiny Causal Transformers as Runtime Anomaly Priors over eBPF Telemetry*
**类型**: 实验论文（系统 + 测量），目标 8 页（双栏）
**一句话卖点**: 用 0.84M 参数的 tiny causal Transformer 在字段级离散化的 eBPF 遥测上学习"行为语法"，以 token 交叉熵惊讶度做运行时异常检测，给出误报率的数学上界，并在梯度隔离靶场上完成逐层可比的端到端验证。

---

## 摘要草稿（≤150 词）

> 主机运行时异常检测长期在表达能力与可运维性之间失衡：重型深度模型难以给出可审计的告警依据，基于规则的方案又无法覆盖行为组合空间。本文提出 Behavior Grammar：将 eBPF（Tracee）采集的主机行为事件做字段级离散化，每个事件编码为 7 个 token 的"语法句子"，用 0.84M 参数的小型因果 Transformer 学习正常行为的条件分布；异常分定义为 token 交叉熵（惊讶度），经事件级 max 与 EWMA 滑窗聚合后与基线 p995 分位数阈值比较，词表外 token 必报。该阈值选择使稳态误报率具有数学上界。我们在自建梯度防御靶场（L0–L4 差量克隆 VM）上验证：87,605 token 基线上 val ppl≈1.1，真实留出集误报率 1.5%（上界 0.5% 名义 + 分布漂移项），三类合成异常全部检出且分数超阈值一个数量级。

---

## 预期贡献声明（3 条，全文围绕此展开）

- **C1 — 字段级离散化的行为语法表示（field-level discretization）**：论证对结构化遥测直接做字段级符号化优于学习连续表示（为何不选 VQ-VAE 路线，见 §3.2），获得可审计、可词表化、可给 UNK 语义的 token 空间。
- **C2 — 误报率的数学上界**：p995 分位数阈值 + 分数构造（max→EWMA）下，稳态误报率可被先验约束；这是本方法与"调出来的阈值"类工作的本质区别。
- **C3 — 梯度靶场测量方法论（graded-range measurement methodology）**：L0–L4 同镜像差量克隆逐层叠加防御栈，使"检测栈每一层的可见性/开销"可被归因测量，而非整机黑盒对比。

## 1. Introduction（约 0.75 页）

要点：

- 动机：主机端运行时检测的核心困难不是"模型不够大"，而是 (a) 遥测是异构结构化事件流，直接套序列模型会丢失字段语义；(b) 告警需要可审计依据与可控误报；(c) 防御效果测量缺乏隔离可比的实验环境。
- 核心观察：正常主机行为在字段级是高度"合文法"的——进程名、父进程、UID、目标分级、时间间隔的组合分布极窄；攻击行为要达成目的就必须在某些字段组合上"不合文法"。这等价于把异常检测转化为条件概率估计问题，small model 足够，因为语法本身很小。
- 关键数字前置：0.84M 参数、4 层 d_model=128、ctx=128；val ppl≈1.1；τ=3.14；留出误报率 1.5%；合成异常分数超 τ 一个数量级。
- 贡献列表（C1/C2/C3）+ 章节路线图。
- 论证目标：让审稿人接受"tiny model 是特性不是妥协"——模型规模由语法复杂度决定，而非由 benchmark 军备竞赛决定。

## 2. Related Work（约 0.75 页）

要点（每条锚点写"做了什么—与我们的区别—我们借用什么"）：

- **DeepLog（日志序列异常检测线）**：DeepLog 用 LSTM 对日志 key 序列建模，开启"序列惊讶度"范式。区别：它建模的是日志事件类型的单字段序列；我们建模字段级多 token 联合条件分布，惊讶度可定位到具体字段（可审计性来源）。借用：条件分布→异常分的总体范式。
- **VQ-VAE 异常检测线**：用向量量化学习离散 latent codebook 再做重构/密度异常检测。区别：VQ-VAE 的 codebook 是学出来的、无字段语义、不可审计，且重构误差对高基数分类字段（进程名、argv）不稳定；我们主张对已知 schema 的结构化遥测，离散化规则应由 schema 决定而非学习（对应 C1 的论证核心）。借用：离散表示带来 OOV/UNK 语义的直觉。
- **MalConv**：raw byte 端对端恶意软件静态检测，说明"放弃特征工程、让模型自己学"在静态 PE 上可行。区别：我们走相反方向——运行时遥测是已结构化数据，字段级 tokenization 是"保留先验"而非"放弃先验"；两者对照说明表示选择应由数据结构决定。
- **gym-malware / MERLIN（威胁背景）**：RL 自我改造恶意软件可针对单一检测器演化逃避。定位：本文检测器不宣称抗对抗自适应，但其检测面在行为层而非样本层，且靶场方法（C3）正是为评估此类威胁准备的实验设施；留给立场论文（姊妹篇）做均衡分析。
- **Host-based IDS 综述**：系统调用序列（Hofmeyr 线）、audit log、eBPF 遥测三代 HIDS 脉络。区别：我们落在第三代但以语言建模式条件分布取代 n-gram/规则，并补上误报率上界这一前人缺失的运维性质。

## 3. Threat Model & 设计原则（约 0.5 页）

- **3.1 Threat Model**：攻击者已获主机内代码执行能力（post-exploitation 阶段），可执行任意进程、发起网络连接、伪装进程名；不覆盖内核级 rootkit 对 eBPF 采集本身的致盲（列入 Limitations）；不假设攻击者知道模型参数（黑盒），但在 Discussion 中讨论白盒自适应攻击。
- **3.2 设计原则**：
  - P1 可审计优先：每个告警必须能回答"哪个字段的哪个 token 不合文法"。
  - P2 误报先验受控：阈值不靠调参而靠分位数论证（C2）。
  - P3 模型规模服从语法规模：参数预算由 token 空间与 ctx 决定。
  - P4 实验可比性：一切结论在梯度靶场分层下给出（C3）。

## 4. System Design（约 1.25 页）

- **4.1 遥测采集**：Tracee/eBPF，事件集合 sched_process_exec、security_socket_connect；rsyslog 汇聚到分析端；采集与打分解耦。
- **4.2 Tokenization（C1 主体）**：每事件 7 token：
  1. 事件类型；2. 进程名；3. argv 骨架（参数名保留、值归约）；4. 父进程名；5. UID 分级；6. 网络目标分级（内网/公网/端口档）；7. 距前一事件时间间隔分桶。
  - 论证点：连续字段（时间间隔、端口）的分桶粒度选择是偏差-方差权衡；argv 骨架保留"语法位置"丢弃"语义值"，使 base64 载荷这类攻击以骨架异常或长度桶异常显形。
  - **为何不用 VQ-VAE**：(a) codebook 无字段语义，告警不可审计，违背 P1；(b) 高基数字段上量化误差主导重构误差，惊讶度失真；(c) OOV 语义是 schema 天然给出的（UNK 必报），学习式 codebook 没有等价物；(d) 训练成本与调参面更大，违背 P3。
- **4.3 模型**：tiny causal Transformer，4 层、d_model=128、ctx=128、0.84M 参数；在 token 流上做 next-token 预测，学习 P(token_t | 历史)。
- **4.4 打分管线**：token 交叉熵 → 事件分数 = 事件内 7 token 的 max（定位最差字段，对应 P1）→ EWMA 滑窗聚合 → 与 τ 比较；**UNK token 直接告警**（词表外=语法外）。
- **4.5 阈值与误报上界（C2 主体）**：τ 取基线分数分布的 p995 分位数（实测 τ=3.14）。论证：在基线分布平稳假设下，单窗误报率 ≤ 0.5%（分位数定义）+ EWMA 聚合的上界修正项；分布漂移时给出漂移项的刻画（留出集实测 1.5% 与此一致，正文给出分解）。

## 5. Implementation（约 0.5 页）

- 数据：87,605 token 基线语料，采集自 L0 裸基线 VM 的正常运维负载（写明采集窗口、事件构成比例、train/val 划分）。
- 训练：标准 next-token 目标，写明 optimizer/epochs/早停（val ppl≈1.1 处收敛——ppl 接近 1 说明正常行为条件分布极窄，本身是个发现）。
- 打分管线：流式实现，EWMA 半衰期、窗口参数列出。
- 靶场（C3 设施描述）：libvirt 隔离网络（无出网路由 + iptables 兜底）、同 cloud 镜像 qcow2 差量克隆、L0 裸基线 → L4 完整检测栈逐层叠加、rsyslog 遥测汇聚、快照一键重置。
- 已知坑：打分管线曾存在 off-by-one 对齐 bug（token 与事件错位），被正常对照组分数异常抓出并修正——记入 E5 而非掩埋。

## 6. Evaluation（约 2.25 页，全文重心）

- **E1 基线建模质量**：val ppl≈1.1；table1 给出基线统计（token 数、词表大小、各字段熵、事件构成）；分析：ppl 接近 1 验证了"正常行为语法极窄"的核心假设，也说明模型容量 0.84M 是过量而非不足（支撑 P3）。
- **E2 合成异常检出**：三类用例——(a) 高端口外联（目标分级字段越界），(b) base64 参数（argv 骨架字段异常），(c) 伪装进程名（进程名×父进程/路径组合不合文法）；结果：全部检出，分数超 τ 一个数量级；fig4 给出检出率×阈值曲线（对阈值选择的鲁棒性）；table2 逐用例给出定位到的字段 token（展示可审计性 P1）。
- **E3 误报率与理论上界验证**：真实留出集误报率 1.5% vs 名义上界 0.5%；分解出漂移项（基线采集窗口与留出窗口的行为差异），验证 C2 的上界结构成立且漂移项可测；讨论 EWMA 窗口对突发误报的抑制。
- **E4 梯度层间可见性对比（L0 vs L2）**：同一攻击负载在 L0（裸基线）与 L2（部分防御栈）下分别测量：检测分数、遥测完整度、层引入的开销；论证 C3——只有差量克隆+逐层叠加才能把"哪一层看见了什么"归因清楚，整机黑盒对比做不到。
- **E5 off-by-one 案例（验证纪律）**：完整叙述 bug 如何被正常对照组抓出、根因（token 序列与事件边界错位）、修正前后分数差异；作为方法论论点：**异常检测系统的验证必须包含"已知正常"对照**，否则管线 bug 会以"低误报"的假象混入结果。

## 7. Discussion（约 0.5 页）

- tiny model 的部署含义：CPU 实时打分、可嵌入 agent、无 GPU 依赖。
- 白盒自适应攻击面：攻击者若刻意维持"合文法"行为可压低分数——但合文法约束本身限制了攻击者的行动空间（与姊妹篇立场论文的"暴露守恒"呼应）。
- 与签名/规则系统的组合：本方法作为 prior，规则作为已知威胁的 precision 层。

## 8. Limitations（约 0.25 页）

- 基线分布漂移是误报主要来源，长期部署需要基线更新机制（未实现）。
- 不防御内核态对 eBPF 采集的致盲；不覆盖无进程/网络行为的纯内存攻击。
- 合成异常三类不等于真实 APT 覆盖度；真实攻击数据受合规限制（见 dual-use 声明）。
- UNK 必报策略在软件频繁更新的环境会产生词表膨胀压力。

## 9. Conclusion（约 0.25 页）

- 重述三点贡献；落点：异常检测的研究重心应从"更大的模型"转向"更好的表示 + 可证可测的运维性质"。

## 风险与 dual-use 声明草稿

> 本工作为防御定位：检测器、靶场与合成异常用例均用于提升防御方对主机行为的可见性。全部实验在 libvirt 隔离网络（无出网路由、iptables 兜底）内的差量克隆 VM 上完成，恶意行为仅为三类受控合成用例，不涉及真实恶意软件样本、不包含可在互联网传播的攻击代码。基线遥测采集自作者自建环境，不含第三方个人数据。打分管线的细节公开有助于防御复现；我们评估其被攻击者用于规避检测的风险低于其防御价值——规避本检测器要求攻击者在全部字段上维持"合文法"行为，这本身就压缩了攻击者的行动空间。靶场构建方法将在遵守上游组件许可证的前提下开源。
