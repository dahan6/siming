# 司命（Siming）— 行为语法检测引擎

**完整系统文档 v4.0**

---

## 一、概述

司命是一个主机行为异常检测引擎，将系统运行时行为视为**结构化语言**，用紧凑的 Transformer 模型学习其"语法"（正常分布），偏离即异常。

核心设计理念：
- **不依赖签名/IOC/规则**——学正常行为分布，而非枚举已知攻击
- **多网融合**——统计 + 语义 + 时序 + 自适应四层独立检测，交叉确认降误报
- **可审计**——每条告警标注触发维度、行为意图、置信度，而非黑盒
- **可部署**——CPU 实时推理，模型 3.6MB，无 GPU 依赖

## 二、系统架构

### 2.1 数据流

```
宿主机
  │
  ├─ auditd execve 事件（零遗漏进程执行捕获）
  │
  ▼
8-token + PREV 离散化
  ET:EXEC | PROC:cat | ARGV:N1P | PREV:fileread | PARENT:bash | UID:1000 | DST:NONE | PC:ETC_PASSWD | DT3
  │
  ├──→ 统计层（TinyGPT prior + EWMA）
  ├──→ 语义层（对比学习 + 分类头 + 后置规则）
  ├──→ 时序层（CV + FFT + 多尺度）
  ├──→ 自适应层（变体容忍匹配 + 自动模式发现）
  │
  ▼
六网融合判定
  P0 交叉确认 → 自动处置
  P1 已知攻击 → 高置信度告警
  P2 语义独判 → 告警
  P3 统计独判 → 参考告警
  P4 时序/FFT → 机器行为告警
  P5 弱信号 → 记录
  │
  ▼
告警 + ATT&CK 技术 + 置信度 + 自动响应
```

### 2.2 六网融合管道

| 层级 | 触发条件 | 置信度 | 响应动作 |
|------|---------|--------|---------|
| **P0** | 统计层异常 + 语义层攻击 | 最高 | 自动处置（杀进程/阻断） |
| **P1** | 自适应层命中已知攻击模式（rebirth/C2/SUID 等） | 高 | 告警 + 取证 |
| **P2** | 语义层独判为攻击（置信度 ≥ 0.7） | 中 | 告警 |
| **P3** | 统计层独判（NLL 超 τ 或 EWMA 超 baseline） | 中 | 参考告警 |
| **P4** | 时序层连续 3+ 次异常 / FFT 检测周期 | 中 | 告警（机器行为） |
| **P5** | 弱信号（自适应层低危） | 低 | 记录不告警 |

## 三、检测层详解

### 3.1 统计层

**模型**：TinyGPT（4 层因果 Transformer，0.90M 参数，128 维，4 头，上下文 128）

**输入**：9-token（8-token + PREV 前事件进程类别）

**PREV 类别压缩**（17 类）：
```
PREV:system | PREV:snap | PREV:kernel | PREV:pkg | PREV:shell |
PREV:fileread | PREV:search | PREV:netrecon | PREV:procrecon | PREV:log |
PREV:priv | PREV:nettool | PREV:lang | PREV:parser | PREV:sec | PREV:misc | PREV:other
```

**检测机制**：
1. 逐 token NLL（负对数似然）= 模型对该 token 的"惊讶度"
2. per-slot τ 标定（p99.5 + 最小阈值保底 3.0）
3. EWMA 滑动窗口（自适应 baseline，warmup 100 事件标定 p99，后续事件与 baseline 对比）
4. z-score 异常（当前 EWMA 偏离 baseline >3σ）

**效果**：
| 指标 | 值 |
|------|-----|
| 词表 | 333 tokens |
| 良性 FPR | 3.9% |
| exfil TPR | 54% |
| lateral TPR | 100% |
| privesc TPR | 33% |
| persist TPR | 6% |
| recon TPR | 17% |

**设计意图**：统计层擅长抓"没见过的组合"（exfil 的 cat→curl 组合、lateral 的 ssh→scp 组合），不擅长抓"用正常命令做坏事"（persist/privesc 命令太常见）。后者交给语义层。

### 3.2 语义层

**模型**：对比学习投影头（128d→128d + BatchNorm + L2 归一化）+ 分类头（128→128→6）

**训练流程**：
1. 对比学习预训练（InfoNCE loss，正样本=同行为类别序列，负样本=不同类别）
2. 分类头微调（6 类：benign/recon/persist/exfil/privesc/lateral）
3. focal loss（γ=2.0，对难分样本加权）+ 类别平衡权重

**后置规则过滤**（消除误报）：
- sudo 的 UID:0 → benign（合法权限切换）
- systemd-executor/systemd-resolve/modprobe → benign（系统守护进程）
- 28 种良性命令（readlink/dash/grep/head/cat/find/du/dig/bash/chmod 等）→ benign
- 条件白名单：find/chmod 在非 SUID 操作时 → benign
- 置信度 < 0.7 → benign

**效果**（融合管道内）：
| 指标 | 值 |
|------|-----|
| benign 准确率 | 84.4% |
| recon 准确率 | 93.9% |
| persist 准确率 | 90.4% |
| exfil 准确率 | 100% |
| privesc 准确率 | 95.4% |
| lateral 准确率 | 100% |
| 独立 FPR | 3.1%（融合后 0.5%） |

### 3.3 时序层

**三个互补检测器**：

**CV 分析器**（已有）：
- 按进程维护时间戳，计算间隔的变异系数 CV = σ/μ
- CV < 1.5 = 机器节奏（anomalous），CV > 2.0 = 人类节奏（normal）
- UID 过滤：系统进程（UID 0/1）不做时序检测
- 连续 3 次异常才报（避免单次噪声）

**FFT 周期检测**（新增）：
- 对事件时间戳重采样到均匀网格 → 直方图 → FFT
- SNR > 5.0 = 有固定周期信号（C2 信标/定时回连）
- 60 秒 C2 信标：SNR=25.9，检测周期 59.6s（精确）
- 人类随机行为：SNR=2.9（正确不报）

**多尺度 CV**（新增）：
- 1 分钟/5 分钟/15 分钟三个窗口同时分析
- 短窗口抓快速回连，长窗口抓低速活动

**隐翅虫验证结果**（VM 遥测）：
| 进程 | 良性 CV | 隐翅虫 CV | 倍差 |
|------|---------|----------|-----|
| sleep | 9.786 | 0.310 | 31.6× |
| head | 3.298 | 0.792 | 4.2× |
| systemctl | 2.446 | 1.178 | 2.1× |
| 检测率 | — | 15/15 | — |
| 误报 | — | 1/15 | — |

### 3.4 自适应层

**5 个检测器 + 1 个通用模糊匹配**：

| 检测器 | 触发条件 | 严重度 |
|--------|---------|--------|
| MORPH_TRANSFORM | cp→chmod→setsid→rm（变体容忍，允许 1-3 个噪声插入） | 5 |
| DISGUISE_C2 | 伪装进程名（node/python3/go-build 等 12 个）外联 EXT:HIGH | 5 |
| SUID_PRIVESC | python3 UID:0 无 sudo 链 | 5 |
| RECON_UNIFORM | 6+ 种侦察命令均匀轮换（max/min < 3） | 3 |
| SLEEP_STEPPING | sleep→动作→sleep 交替（≥8/20 sleep + ≥6 次交替） | 3 |
| 序列模糊匹配 | 从 patterns.jsonl 加载序列模板，滑动窗口模糊匹配 | 4-5 |

**变体容忍机制**：
- 允许关键命令之间插入 1-3 个噪声命令（sleep/dash/env/date/echo 等）
- 攻击者无法通过"加 sleep 打断序列"来绕过检测
- 测试：cp→sleep→chmod→env→setsid→sleep→rm → ✅ 仍触发

**自动模式发现**：
- 从 patterns.jsonl 的 approved sequence 条目自动提取 PROC 序列
- 滑动窗口模糊匹配，无需硬编码

### 3.5 语义嵌入（可选层）

**模型**：char-CNN 文本编码器（64→128→128 维）+ 对比学习

**数据**：209 个 token 的自然语言描述（如 PROC:cat → "read and display file contents..."）

**效果**：
| 类别 | 类内距离 | 类间距离 | 聚类比 |
|------|---------|---------|--------|
| file_read | 0.429 | 18.090 | 42.2× |
| net_tool | 0.364 | 17.426 | 47.9× |

**注入方式**：α × 语义 embedding + (1-α) × 原始 embedding（α=0.3 默认不用，等更多数据后启用）

## 六、Token 格式定义

### 9-token 表示（8 基础 + 1 PREV）

| 槽位 | 含义 | 示例 |
|------|------|------|
| ET | 事件类型 | EXEC / CONN |
| PROC | 进程名 | cat / ss / crontab / python3 |
| ARGV | 参数骨架 | N1P（1 个参数+路径）/ N2-（2 个参数无路径）/ ARGV0（无参数）|
| PREV | 前事件进程类别 | fileread / netrecon / shell / system |
| PARENT | 父进程 | bash / systemd / sudo / ? |
| UID | 用户 ID | 0（root）/ 1000（普通用户） |
| DST | 网络目标 | NONE / EXT:HIGH / LAN / OTHER |
| PC | 路径分类 | ETC_PASSWD / ETC_CRON / SSH_KEYS / TMP / HOME_RC / NONE |
| DT | 时间间隔桶 | DT0(<1ms) / DT1(<10ms) / ... / DT6(>60s) |

### 参数骨架编码

```
ARGV:N{n}{flags}

n = 参数个数（去掉 argv[0]）
flags:
  P = 有路径参数
  B = 有 base64 编码参数
  U = 有 URL 参数
  - = 无特殊参数
```

## 七、训练流程

### 7.1 统计层训练

```bash
# 1. 采集良性数据（auditd）
echo 5uayq7ek | sudo -S python3 collect_auditd.py --parse /var/log/audit/audit.log --out data/audit_all.jsonl

# 2. 加 PREV 槽 + 类别压缩
python3 stat_layer_upgrade.py --prep data/audit_all.jsonl --out data/audit_prev.jsonl

# 3. 训练（GPU 推荐）
python3 train_prior.py data/stat_train_v2.jsonl model-stat-v3
```

### 7.2 语义层训练

```bash
# 1. 自动弱标注
python3 auto_labeler.py data/audit_all.jsonl --out data/audit_labeled.jsonl

# 2. 生成合成攻击
python3 -c "from auto_labeler import gen_recon, gen_persist, ...; ..."

# 3. 构建训练集 + 对比对
python3 -c "..."

# 4. 对比学习 + 分类头训练
python3 train_semantic.py
```

### 7.3 语义嵌入训练（可选）

```bash
# 1. 准备描述语料
python3 semantic_descriptions.py

# 2. 训练 mini-encoder
python3 train_semantic_encoder.py
```

## 八、部署流程

### 8.1 新机器部署

```bash
# 1. 安装依赖
pip3 install torch numpy scikit-learn

# 2. 安装 auditd
sudo apt install auditd
sudo auditctl -a always,exit -F arch=b64 -S execve -k exec_log
sudo auditctl -a always,exit -F arch=b32 -S execve -k exec_log

# 3. 采集 20 分钟良性基线
sudo python3 collect_auditd.py --duration 1200 --out data/onboard_benign.jsonl

# 4. 标定 slot_tau

# 5. 启动检测
python3 fusion_pipeline.py --eval /var/log/audit/audit.log

python3 deploy_scorer.py model-stat-v3
```

```bash
# 1. 采集新数据

cat data/audit_all.jsonl data/new.jsonl > data/combined.jsonl
```

## 九、已知限制

### 9.1 数据限制
- **真实攻击 TPR 未验证**——所有 TPR 数字在合成攻击上测得
- **单机数据**——只有一台宿主机 + 7 台 VM 的良性基线
- **无多发行版验证**——只在 Ubuntu 上测过

### 9.2 架构限制
- **窗口级分类过拟合**——窗口 Transformer 在混合数据上 100% 训练准确率但 48.6% FPR，已回退到单事件分类
- **语义嵌入轻微负贡献**——α=0.3 注入后掉点 2%，当前数据规模下语义先验不如序列统计强
- **无实时管道**——fusion_pipeline.py 是批处理脚本，不是实时守护进程

### 9.3 工程限制
- **无自动响应**——只写告警，不杀进程/阻断网络
- **无 7×24 稳定性验证**——内存泄漏/崩溃恢复/日志轮转未测
- **无 SIEM 集成**——告警输出到 jsonl 文件，不接 syslog/journal
