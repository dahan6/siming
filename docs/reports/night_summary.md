## 三、最终结果

- 达标模型：`detector/model-host-r2/prior.pt`（0.85M 参数，词表 167）
- 关键指标：20000 事件留出 FPR(EWMA)=1.00%；合成异常 4/4 检出；余量 8.8x(vs p95)/5.1x(vs τ)
- τ 扫描显示可行工作区间 [3.0, 4.5]，推荐 τ=3.5（FPR 0.70%、余量 3.9x，比压线的 p995 工作点有安全边际）
- 与 VM 版对比：宿主机正常分布尾部显著更厚（稀有合法活动多），但数据量路线同样收敛；
  VM 版的"调阈即可"经验在宿主机不成立，必须靠数据压缩尾部
- 部署验证：deploy_scorer 对 69.9 万事件全流打分，384 条告警（0.05%），全为稀有合法活动，无语义错误

## 四、发现与结论

已确认的发现（r0 彩排轮 + τ 敏感性分析）：

1. **观察者污染是真实工作机上最大的误报源**：夜间管线自身活动（tee/date/nice 包裹的 python 进程）落在留出窗口即触发误报。
   这不是模型缺陷——模型忠实地报告了"训练分布中没有的进程模式"。含义：真实部署时，
   监控系统自身的进程必须进入训练语料或被显式标记，否则监控系统自己就是头号告警源。
2. **次要噪声源**：chronyd 高端口 NTP 连接——系统服务的不规则网络行为。
3. **纯调阈无解（定量证据）**：r0 留出数据上，FPR≤1% 需要 τ≥8，但此时最低异常分/τ 余量仅 0.98x（<3x）；
   τ=2.435 时余量 3.2x 但 FPR=3.75%。双判据的交集为空 → 必须压缩正常分布尾部（更多数据），
   而非移动阈值。这是"数据量路线"的直接证据。
4. 合成异常检出能力在 r0 已达标（4/4，余量 3.5x），瓶颈单方面在误报率。

轮 1 及之后的结论：

5. **数据量路线被验证**：FPR 3.75%→1.75%→1.00% 单调下降，余量 3.5x→5.7x→8.8x 单调上升，趋势干净。
6. **最重要的方法论发现——评估窗口必须是分布，不能是快照**：r2 用 800 事件（≈20 秒）留出判 FAIL(5.50%)，
   改 20000 事件（≈8 分钟）后 PASS(1.00%)，结论完全反转。20 秒窗口被 watch_router.sh 轮询爆发主导。
   800 个采样点 ≠ 800 个独立样本；时间聚集性使短窗口成为随机快照。此教训对所有时序异常检测评估通用。
7. 误报的最终画像是"真实但稀有的合法活动"（监控轮询/稀有管理通道/系统服务），
   吸收方向是天级基线覆盖昼夜节律，而非模型改动。
