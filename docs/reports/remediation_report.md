# 司命 · P1 自动消杀闭环验证报告

日期：2026-07-30 ｜ 环境：防御 VM defense-atomic-0（快照还原保证每轮干净起点）
**结论：11/11 攻击-检测-消杀-验证全链路通过（覆盖 10 个 ATT&CK 持久化技术）。
已知技术族内，"检出即消杀"闭环成立。**

## 1. 链路设计

```
快照还原 → 攻击植入 → verify(应 DIRTY) → tracee 轨迹 → 三网融合检测
        → 告警>0 触发 → 执行 cleanup（manifest 映射）→ verify(应 CLEAN) → 矩阵记录
```

- 响应映射：`range/atomic/collect_manifest.yaml` 每技术 attack/cleanup/verify 三元组
- 编排器：`range/scripts/remediate_round.sh`；检测：`detector/detect_in_trace.py`
- 安全边界：所有消杀动作仅在防御 VM 内执行，宿主机零响应动作

## 3. 归因与消杀的关系（重要）

- 归因正确 3/11、同族 2/11、错误 2/11、无归因但检出 4/11
- **本轮消杀不依赖归因**：cleanup 由"本轮跑了什么技术"决定（测试编排可知）。
  实战中归因错→消杀错，所以归因精度是上线自动消杀的前置条件
- 分层结论：**检测层（有攻击）10/10 可信；归因层（哪种攻击）约 6/10——
  自动消杀当前只应对"高置信归因"（原型精确命中）开放，其余走人工确认**

## 4. 遗留

1. 归因精度提升（环境扰动采集拉开类间距）——自动消杀全面化的唯一卡点
2. 二次验证采集：cleanup 后再采一段轨迹确认无残留行为（当前 verify 只查文件）
3. 响应动作幂等性与回滚（cleanup 失败时的重试/上报通道）
