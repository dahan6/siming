# 行为语法检测器 M2 — 序列先验验证报告

日期：2026-07-30 ｜ 数据：`detector/data/tokens.jsonl`（12515 事件 × 7 token）｜ 模型：`detector/model/prior.pt`

## 1. 实验设置

- **任务**：用因果 Transformer 学习正常主机行为 token 流的条件分布 p(x_t | x_<t)，以事件惊讶度（事件内 token NLL 取 max，记 s_ev）做异常检测。
- **模型**：TinyGPT，d_model=128、4 层、4 头、上下文 128 token，词表 134（min_freq=2），**参数量 0.84M**。
- **训练**：8 epoch、batch=64、AdamW lr=3e-4，85/15 时序切分。**最终 val_loss 0.077（val ppl 1.1）**。
- **判定规则**（双标准）：s_ev > τ（τ = 基线逐 token NLL 的 p995 = **3.141**）**或**事件含词表外 token（UNK≥1）即判异常；EWMA(α=0.3) 仅作窗口参考分。
- **打分对齐**：位置 j 的 token 由位置 j-1 的 logits 预测（见 §6 的 off-by-one 修正）。

## 2. 基线分布

checkpoint 内验证集逐 token NLL 统计：mean=0.077，p50≈0.000，p95=0.276，p99=2.211，**p995=3.141（即 τ）**。

全量 12515 事件打分后的事件级 s_ev 分布（`fig1_baseline_nll_dist.png`，仅画判正常的 12429 条）：p50≈0.0004、p95=0.46，高度集中于 0 附近、右尾短，τ=3.14 远在主体分布之外——说明 ppl≈1.1 的先验对正常流已接近"背下来"，阈值有充分的分离余量。

## 4. 误报分析（86 条判异常事件抽查归类）

> 参照：此前在干净留出 800 事件上测得误报率 1.5%（p50=0.004 / p95=1.18）。全量 0.69% 的标注率与该水平一致。

抽查 10 条（5 条仅超τ + 5 条 UNK），结合 86 条的高频模式统计，归为四类：

1. **低频合法服务行为的分布尾部**（仅超τ类主体）：`systemd-resolve → DST:LAN:HIGH`（6 次）、`sd-resolve UID:996 → DST:OTHER`（5 次）、`cron DT4/DT5`（3 次）、`systemd UID:1000 外联`（5 次）。都是真实但少见的系统服务组合，s_ev 集中在 3.2–5.8，刚过阈值。属统计意义误报，可用时间衰减/服务白名单吸收。
2. **采集解析截断产生的怪异进程名**：`PROC:9`（s=8.9–9.4，全量最高分区）、`(wnloader)`、`(tmpfiles)`、`(modprobe)`、`(spawn)`、`bcache-export-c`、`50-landscape-sy` 等。括号名是长进程名被截断的解析产物，进不了词表（min_freq=2）触发 UNK，或构成罕见转移触发超τ。**根因在采集侧**，应修解析器而非模型。
3. **罕见管理命令组合**：`nohup → bash`、`seq`、`package-data-do` 等低频 EXEC 链，s_ev 本身不高（0.3–1.2），靠 UNK 标准捕获——这类恰恰是检测器设计要保留的灵敏度。
4. **冷启动上下文缺失**：i=0 首事件 s_ev=7.06，无前文导致首个 token 高惊讶。工程上应对每流首事件豁免或预热窗口。

## 5. 合成异常检出

`synth_anomaly_test.py` 离线验证（不触靶场）：

| 用例 | s_ev | τ=3.141 | 判定 |
|---|---|---|---|
| A 高端口外联 | 19.39 | >τ | 检出 |
| B base64 参数 | 17.61 | >τ | 检出 |
| C 陌生进程伪装（`.kworker_u9`） | 9.71 | >τ | 检出 |
| D 正常对照（手造 `ps` 事件） | 8.03 | >τ | 误标异常 |

**关于 D**：手造事件不等于"分布内正常事件"——`ps/ARGV:N2-/UID:1000/DT3` 这个具体组合在训练流里没出现过，先验如实给出高惊讶。这是预期现象而非回归：它恰恰说明模型对"未见过的组合"敏感，但也提醒手工构造的用例不能当作校准过的阴性对照，阴性对照应取自真实留出流。

**阈值扫描**（`fig3_threshold_curve.png`，用 labeled 全量近似真实流量误报率）：曲线形态为单调陡降的阶梯——τ=0.5 时 FPR≈5%，τ=2 时 1.85%，**当前工作点 τ=3.14 处 FPR≈0.58%**，τ=5 时 0.25%，τ≥10 降为 0（全量真实事件 s_ev 最大仅 9.81）。三个合成异常分数（9.71–19.39）全部落在零误报区边缘或之内：τ 在 3.14–9.7 整个区间内三例全检出，工作点有 ~3 倍检出余量；但若为追零误报把 τ 提到 9.8 以上，会漏掉最弱的 C 例（9.71），不建议。

## 6. 验证纪律案例：off-by-one bug 的发现与修正

初版打分把位置 j 的 logits 直接当作对位置 j token 的预测，错位一位：模型实际学的是 p(x_t | x_<t)，位置 j 的 logits 预测的是位置 j+1。错位导致每个 token 都被"上一个 token 的分布"评分，正常事件分数整体抬高、基线分位数失真，τ 失去语义。修正为 `nll = -lp[start-1 : L-1].gather(tgt=window[start:L])` 后，正常留出 p50 降到 0.004、与训练 val_loss 0.077 自洽，合成异常与基线拉开 3–6 倍。**教训：惊讶度类检测器上线前必须用一个"已知正常留出 + 已知合成异常"的双向 sanity check 验证打分对齐，单看一边都发现不了错位。**

## 7. 局限性与下一步

- **基线单一主机/单一时段**：tokens.jsonl 来自单一靶场时段，跨主机、跨时段漂移未验证；τ 需要在每个部署环境重估。
- **解析截断污染**：§4 第 2 类误报根因在采集侧（进程名截断、括号名），应先修 parse_events 的截断逻辑再重训词表。
- **max-pooling 的事件分**：s_ev 取事件内 max NLL，对单 token 毛刺敏感；可对比 mean/top-k 均值的事件分。
- **UNK 双标准未消融**：14 条仅 UNK 判异常中混有解析噪声和真实罕见行为，需消融实验量化 UNK 标准的净收益。
- **合成异常仅 3 类**：检出结论仅限高端口外联/可疑参数/进程伪装三类，低速率、模仿型攻击的检出率未知。
- 下一步：修解析截断 → 多主机多时段基线 → EWMA 窗口分的告警级联（单事件超τ + 窗口分联合判据）→ 注入回放做检出率-误报率联合曲线（ROC）。
