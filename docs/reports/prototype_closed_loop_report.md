## 3. 关键发现（按价值排序）

1. **PATHCLASS 维度是可分性的关键修复**：初版 ARGV 骨架（N1P=一个路径参数）抹平了
   "写哪个文件"，tee→rc.local/.bashrc/ld.so.preload 三技术嵌入不可分（loss 卡 3.0）。
   加入 PC 类目（PC:HOME_RC/PC:ETC_LD/PC:ETC_SYSTEMD 等）后 loss 收敛到 0。
   教训：抽象粒度决定检测上限——抹掉攻击的区分性信息，模型再强也分不开。
2. **半径标定不能只看类内分布**：同一 VM 快照重放的样本距离≈0（确定性环境），
   类内 p99 半径退化为 0。改为"类内 max 与良性 min 的几何中点"——用良性分布压出
   可用半径，零误报由构造保证。局限：对"近似变种"的覆盖未在首轮验证（需要环境扰动采集）。
3. **基线污染三连**（本次实验最重要的运营发现）：
   a. r0：管线自身进程落入留出窗口 → FPR 虚高
   b. 融合验证：采集管道活动成为最大"异常源"（26.5k 条忠实告警）
   c. 轮 3：用含攻击采集活动的时段训练基线 → τ 膨 5.6 倍、真异常被盖
   结论：训练窗口必须避开自身作战活动；监控/采集/防御基础设施的流量要么进语料要么显式标记。
4. **归因精度落后于检测精度**：T1543.002/T1053.006 的轨迹触发的是 T1574.006 原型
   （attribution 错误）；T1037.004/T1098.004/T1136.001/T1547.006 无 P1 归因
   （靠先验/模式检出）。检测 10/10 但归因约 6/10——原型头的"认出是攻击"达标，
   "认出是哪种攻击"待提升（需要更多样本/环境扰动拉开类间距）。
5. **shell 内建命令在 exec 维度隐身**：echo >> ~/.bashrc 不产生 sched_process_exec，
   这类持久化需文件完整性事件（openat/write）补齐——采集事件集的扩展方向。
