# 司命 · 三网融合打分器全流验证对比报告

日期：2026-07-30 ｜ 打分器：deploy_scorer.py v2（稀有度+上下文+模式库）｜ 模型：model-host-r2
**结论：同数据基础上融合版优于旧版（245 vs 384 条告警，-36%），三网融合逻辑验证通过。
告警暴增段全部位于旧版窗口之后，为模型对采集管道自身活动的忠实报警——观察者污染在管道规模的再现。**

## 1. 实验设置

- 旧版基线：model-host-r2 + 全局 τ(p995)=2.655 + UNK，700k 事件 → 384 条告警（0.055%）
- 融合版：分维度 τ（7 槽位，floor 1.0）+ patterns.jsonl（7 条种子模式），优先级 P1 模式 > P2 上下文 > P3 稀有度
- 打分范围：1,014,966 事件全流（含旧版窗口之后的采集管道活动时段）

## 2. 总量结果

| 范围 | 旧版 | 融合版 |
|---|---|---|
| 同窗口（旧版覆盖段） | 384（0.055%） | **245（0.035%）**，剔除 ET-only 后 130 |
| 窗口后新增段 | — | 26,520（其中采集管道直接相关 1,681） |
| 全流合计 | 384 | 26,765（P1=433 / P2=13,513 / P3=12,819） |

## 3. 归因分析

- **P1 模式命中 433 条**：P-T1041（脚本化网络工具）430 条 + P-T1053（cron）3 条。
  取证：绝大多数是本次采集管道自身活动（sshpass 驱动的 ssh/scp 批量传输）——
  模式语义正确，命中的是"我自己的自动化管道"。
- **P2 上下文 13,513 条**：PARENT(4774)/DST(3918)/DT(≈4600) 维度。
  驱动源：防御 VM 创建、libvirt 网络 churn、采集期的 ssh 爆发——全是模型训练窗口（≤08:00）
  之后新出现的管理行为模式。
- **P3 稀有度 12,819 条**：PROC(7783)/ARGV(6707)。
  驱动源：ssh(14321)/NetworkManager(2084)/libuv-worker(1230)/libvirt 系列（VM 相关新进程模式）。
- **ET 维度开火 7,481 次**：事件类型的"可预测性"主要是突发噪声，语义弱，
  已从报警维度移除（后续版本生效），本报告数字为移除前。

## 4. 结论与教训

1. **同数据对比融合版 -36% 告警量**：分维度判定 + 优先级去重没有引入误报膨胀，反而更准。
2. **告警暴增是数据漂移不是逻辑缺陷**：26.5k 条全部在旧版窗口后，内容为采集管道+建 VM 的
   高强度新管理活动。检测器忠实报告了"这台机器上从没发生过的管理行为模式"。
3. **观察者污染升级到管道规模**：r0 的教训（监控系统自身进程是头号告警源）在更大尺度复现——
   采集管道（sshpass/scp/VM 管理）本身成为最大的"异常源"。运营含义：防御基础设施的
   自身流量必须进训练语料或被显式标记（基础设施白名单），否则防御系统自己报警自己。
4. P2/P3 分布合理：P1 精准稀少（0.04%）、P2 上下文为主力、P3 稀有度兜底——优先级结构符合设计。

## 5. 后续动作

- ET 槽位已移出报警维度（保留参考）
- 基础设施白名单机制：防御管道进程组（sshpass/virsh/scp 采集相关）标记为 infra 类，
  进训练语料而非告警通道——作为部署配置项落地
- 轮 3（PATHCLASS 8-token）重训后用新模型复核本对比
