# 司命 · 新主机自适应上线（onboarding）验证报告

日期：2026-07-31 ｜ 对象：防御 VM defense-atomic-0 作为"另一台主机"（Ubuntu 24.04 服务器，
行为分布与宿主机显著不同）｜ 触发：对抗实验实证司命跨机基线失效（92.5% 误报）

**结论：上线流水线三件套（onboarding 管线 / 漂移触发 / 影子发布）全部建成并验证。
跨机问题的定量答案：基础模型不能直接跨机（A 91.2% / B 76.4%），但本机自训便宜到
近乎免费（3887 事件 + 40 秒训练 → FPR 4.5%，EWMA 0.07%）——"基础训练+逐步学习"的
正确分工是：跨机的是架构与码本，本机先验必须自训且成本极低。**

## 1. 跨机迁移三连实验（核心数据）

宿主机先验（model-host-r3-clean）在 VM 数据（3887 事件）上：

| 策略 | FPR | 分解 | 结论 |
|---|---|---|---|
| A 零适配（宿主机 τ 直接用） | **91.2%** | 超τ 78.7% + UNK 12.4% | 复现红方实验（92.5%），病灶确认 |
| B 方言重校准（VM 数据重标定 τ，不重训） | **76.4%** | 超τ **4.3%** + UNK 72.2% | τ 重校准是手术刀（78.7%→4.3%），但词表才是主战场 |
| C 本机自训（3887 事件，40 秒） | **4.5%** | 超τ 4.5%，UNK≈0 | 唯一出路；数据量上去后向 1% 收敛 |

关键分解：误报由两种成分构成，各有各的解法——
- **方言槽分布漂移**（UID/DST 等）：分钟级重校准可解（78.7%→4.3%）
- **词表覆盖缺失**（VM 58 种 token 宿主机没见过，占 token 流 16.3%）：
  UNK 机制全部报警，**只能靠本机增量学习解**，任何不重训的方案在这里都是死的

## 2. 上线验收（model-vm-0，首轮 3887 事件）

| 指标 | 结果 |
|---|---|
| FPR(原始/EWMA) | 3.27% / **0.07%**（1500 事件留出） |
| 合成异常检出 | 3/4（E-root 外联 4.32 < τ=5.76 临界） |
| E 临界根因 | 基线太小 + VM 上 root 出网是系统服务常态（chronyd/systemd-resolve）→ 触发自动延长学习窗（90 分钟，进行中） |
| **攻击本质序列检出** | **33/33（10 技术全过）** |
| 攻击窗整体告警率 | 6%~30%（0/10）——见 §3 方法论辨析 |

## 3. 方法论辨析：召回率必须在固定误报率下测

本次最重要的实验方法论发现：
- 宿主机模型在 VM 攻击窗告警率 ~80%（表面 10/10 召回）——但它对 VM 良性流也报 91%，
  "召回"是头发丝扳机，无意义
- VM 原生模型攻击窗告警率 6%~30%（表面 0/10）——但窗口 90% 是采集噪声（ssh/sudo 会话），
  对**提取后的攻击本质序列**检出 33/33
- 结论：攻击窗告警率被噪声稀释、被基线 FPR 污染；召回评估必须
  ① 固定 FPR（同一模型良性/攻击同测）② 用攻击本质序列而非全窗口计数

## 4. 三件套验证

### 4.1 漂移触发守护（drift_watch.py）
- 监测词表增长 / 槽位分布漂移，超阈写 RETRAIN_TRIGGER（含原因）
- 演示：注入 800 条新软件生态事件，词表 180→220（+22%>15% 阈值）→ 正确触发

### 4.2 影子发布（shadow_release.sh）
- compare：同一 VM 流上 旧模型 3273 告警 vs 新模型 160 告警（0.05x）——切换依据量化
- promote/rollback 全周期验证（含无备份边界：降级为摘除链接回未部署态）
- 模型+码本配对版本，原子切换（symlink）

### 4.3 onboarding 管线（onboard.sh）
- 静默学习窗（良性活动驱动器 + tracee）→ 解析 → 训练 → 校准 → 自动验收
- 不达标自动延长学习窗（E 用例触发，90 分钟窗进行中，结果待补）

## 5. 对红方实验的回应

红方对抗实验（92.5% 误报）是司命最好的体检报告。本报告的量化分工：
- **跨机通用**：架构、token 语法、码本（原型/模式不依赖本机基线，落地即有 P1 防护）
- **必须本机自训**：先验（词表+分布）——成本已压到分钟级数据 + 秒级训练
- **上线时序**：静默窗内码本护航 + 先验影子模式，验收（FPR+检出）通过才开告警，
  漂移触发后续重训，影子发布保证换版安全
